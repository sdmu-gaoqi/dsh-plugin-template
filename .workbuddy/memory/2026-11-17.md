# 2026-11-17

## 搭建 dsh 插件模板工程（dsh-plugin-template）

- 仓库定位：pnpm workspace 模板，`packages/my-plugin` 是示例插件包，`packages/build` 放构建脚本。
- 构建链路：`packages/build/bin/build.mjs` 遍历 `packages/*`（有 `source/` 即视为包），先 `tsc -p <pkg>/tsconfig.json` 产 `lib/**.js` + `lib/types/**.d.ts`，再对 `source/client.ts` 用 esbuild 打成单文件并套 `window.__ModuleLoader__.load({ id: pkg.name, factory })` 外壳。
- 关键发现（来自 `@deepseek-ai/dsh-client-modules` 的 lib）：dsh 浏览器端用 `<script>`（classic script）加载 `/plugins/<id>/client.js`，文件必须自己调用 `__ModuleLoader__.load` 注册工厂，直出 ESM 一定失败；`dsh.client = { platform（必填）, inject?, immediately? }` 且包必须导出 `exports["./client"]`；模块 id = 包名（与 patch 行 id 无关）。
- 版本坑：`@deepseek-ai/*` 的 `latest`（0.0.1-rc.1 线）传递依赖里有未发布的 `@deepseek-ai/dsh-type-meta`，装不上；要用 `next` 线（0.2.2-rc.3）对齐 dsh 0.2.x。dsh-tools 的 peer 全是精确版本。
- lint 接入 `@wagq/lint-ox`：`.oxlintrc.json` 用 `extends: ./node_modules/@wagq/lint-ox/oxlint/base.json`（+ `env.node`、忽略 `**/lib/**`），scripts 用 `oxlint .` 走默认配置发现；oxfmt 直接 `-c ./node_modules/@wagq/lint-ox/oxfmt.json`，oxfmt 版本必须锁 `0.75.0`（peer 是 caret-on-0.x）。
- 本机环境坑：该会话里 pnpm 11.16 装完只生成 `.pnpm` 不建顶层软链（最小复现也失败），改用 `npm install` 验证；根 package.json 因此加了 `workspaces` 字段兼容 npm。用户自己终端执行 pnpm 应正常。
- 初始化改名：`node packages/build/bin/init.mjs --name <slug>`（根脚本名 `rename`，避免与 `pnpm init` 内置命令冲突），跳过 `packages/build` 与锁文件。
